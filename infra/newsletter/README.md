# Newsletter (Listmonk) — prompt 22 part 3, contract §31.3

Listmonk (AGPL-3.0, free, self-hosted) is the company's own channel: it keeps the
subscribers, their consent and the one-click unsubscribe. The hub keeps only the
mapping of lists to companies and the campaigns it made (migration 0041).

* Opt-in compose profile `newsletter`: `make newsletter-on` / `make newsletter-off`
  (refused over the memory budget). Image pinned (`listmonk/listmonk:v6.2.0` by digest).
* Its own Postgres role and database (`newsletter-provision`, `infra/newsletter/provision.sh`).
* Port `127.0.0.1:9000` only: open the admin page through your own SSH tunnel.
* Admin login: generated by `make env` (`LISTMONK_ADMIN_PASSWORD`), copied to OpenBao
  `kv/hq/newsletter/admin` by `make newsletter-on`.
* The hub calls Listmonk's API with an API user's token in OpenBao `kv/hq/newsletter/api`:
  create the API user in the admin page, then `make newsletter-secret USER_NAME=<name>`.

## What the owner still has to do

1. Sign in once, create the API user, run `make newsletter-secret`.
2. In Listmonk's settings: SMTP of your mail provider (Listmonk's only route out is the
   network `hq-newsletter-out`), the sender address, and the **public root URL**. The
   unsubscribe, opt-in and tracking links must be reachable by readers; Caddy does not
   route Listmonk (your decision: a separate public name, or a Caddy route limited to
   `/subscription/*`, `/link/*`, `/campaign/*`, `/uploads/*`).
3. Listmonk has no native A/B subject test; the hub builds none.
