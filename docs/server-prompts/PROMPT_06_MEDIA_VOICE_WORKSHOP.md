## ۲. فایل‌ها و رسانه (§۱۷.۱)
- **`POST /api/v1/files`** برای مالک: بدنه‌ی خام، سقف حجم **حین stream**، نوع از روی **magic bytes** (نه header)، فهرست مجاز و سقف‌ها دقیقاً طبق قرارداد. فایل در همان انبار فایل‌های موجود (و همان backup)، با `company` از thread مقصد هنگام پیوست.
- **worker پردازش** (بدون مدل): `libvips` یا Pillow برای عکس (حذف EXIF و GPS، thumb وب‌پی ۵۱۲)، `ffmpeg` برای فیلم (poster، تا ۱۲ فریم کلیدی با تشخیص صحنه، حداکثر یکی در هر ۵ ثانیه، استخراج صدا)، و صدا ← §۳. وضعیت `processing → ready|failed` و رویداد `file.ready`/`file.failed` روی stream.
- **`GET /files/{id}?variant=`** با `Range` (پخش فیلم در اپ)؛ `GET /files/{id}/meta`.
- **پیوست در پیام:** `attachments: [file_id]` تا ۱۰ عدد؛ `body` با پیوست میتواند خالی باشد. فایل پیوست‌شده مال شرکت همان thread میشود (RLS).
- **ایجنت‌ها:** عکس به‌صورت **ورودی تصویری** (لبه‌ی بلند ≤ ۱۵۶۸ پیکسل) به مدل میرسد؛ فیلم = فریم‌های کلیدی + متن صدا؛ صدا = متن. **هیچ‌وقت فیلم یا صدای خام به مدل نمیرسد.** llm-router و claude-runtime باید بلوک تصویر را بپذیرند (الگوی `claude-llm` FX پشتیبانی تصویر داشت؛ §۴.۱ نقشه‌ی راه). ابزار تازه‌ی Gateway: `file.view` (A0، فقط فایل‌های شرکت خود ایجنت) — آن را در «Contract notes» بنویس تا به `agents/tools.md` اضافه کنم.
- **تست قبولی:** آپلود هر نوع مجاز؛ رد نوع جعلی (پسوند درست، محتوای نادرست)؛ رد حجم زیاد پیش از پایان آپلود؛ EXIF حذف شده؛ فیلم ۳۰ ثانیه‌ای poster و فریم و متن دارد؛ ایجنت شرکت دیگر به فایل دسترسی ندارد؛ پیام با عکس به یک مدیر، در اجرای او بلوک تصویر دارد (با مدل جعلی بررسی شود).

## ۳. صدای فارسی به متن دقیق (§۱۷.۲)
- **سرویس تازه‌ی `stt`** روی `hq-core`، بدون پورت منتشرشده، uid غیر root، rootfs فقط‌خواندنی، `cap_drop: ALL`، سقف حافظه در هر دو پروفایل (بودجه‌ی حافظه باید پاس بماند).
- **موتور:** `faster-whisper` (MIT) با مدل **`large-v3-turbo`** نسخه‌ی CTranslate2، **int8 روی CPU**، `language="fa"`، beam 5، VAD. مدل یک بار دانلود میشود (revision و sha256 در repo pin)، در volume میماند و سرویس بعد از آن آفلاین کار میکند. **هیچ صدایی از هاب بیرون نمیرود.**
- **نرمال‌ساز فارسی قطعی** (کد، بدون مدل): ی/ک عربی، نیم‌فاصله برای «می/نمی» و «ها/های/تر/ترین/ام/ای»، علامت‌های فارسی (، ؛ ؟)، بدون ترجمه یا بازنویسی. تست واحد با ۵۰ جمله‌ی نمونه.
- **گذر نقطه‌گذاری با مدل سبک** (A0، کلاس کار `stt_punctuation`، P1): فقط نقطه‌گذاری و پاراگراف و چسباندن تکه‌های غلط ASR؛ اگر فاصله‌ی ویرایش در سطح کلمه بیش از ۸٪ شد، **خروجی مدل رد** و متن نرمال‌شده نگه داشته میشود. هر دو متن در لاگ کیفیت.
- **`POST /api/v1/transcribe`** طبق قرارداد؛ صدا به‌صورت فایل نگه داشته میشود؛ پیام ساخته‌شده از صدا `kind: "voice_transcript"` با صدا به‌عنوان پیوست.
- **کارایی:** هدف: ۳۰ ثانیه صدا ← متن در ≤ ۱۰ ثانیه روی همین سرور (با بار عادی). اگر نرسید، `small`/`medium` را **پیشنهاد** کن و عدد بده؛ خودت مدل را عوض نکن.
- **پروتکل کیفیت (۱۰۰ نمونه):** ابزار `make stt-eval` که از پوشه‌ی نمونه‌ها (صدا + متن دقیق) WER حساب میکند و گزارش میدهد. نمونه‌ها را مالک بعداً ضبط میکند؛ تو فقط ابزار و ۵ نمونه‌ی ساختگی برای تست میسازی.
- **تست قبولی:** فایل صدای فارسی نمونه ← متن درست؛ فایل بی‌صدا ← متن خالی بدون خطا؛ فایل خیلی بلند ← `413`؛ نرمال‌ساز؛ رد خروجی مدلی که متن را عوض کرده (مدل جعلی).

## ۴. کارگاه کد (§۱۷.۳)
**اصل:** کارگاه **هیچ‌وقت به production دست نمیزند.** فقط شاخه‌ی `hq/<session-ref>` push میشود و PR باز میشود؛ merge و deploy همچنان تصمیم با مُهر مالک است. ریپوهای دیگر (TradeYar، FX، Pro-Chart) طبق قانون ۲ فقط با اجازه‌ی صریح مالک تغییر میکنند: **grant مُهرخورده‌ی مالک همان اجازه‌ی صریح برای همان سشن است** (مرکز Change Request، F6 نقشه‌ی راه).

### ۴.۱ کنترل‌پلن در هاب (این پرامپت کامل میسازد)
- جدول‌ها: `workshop.workspaces`، `workshop.grants`، `workshop.sessions`، `workshop.events` (append-only)، با RLS شرکت مثل بقیه و audit برای هر تغییر.
- **seed workspaceها از فایل** (`apps/api/seed/workspaces.yaml`؛ داده، نه کد): هر شرکت ریپوی محصول خودش، به‌علاوه‌ی `HQ-HUB` برای همین ریپو. مالک بعداً از اپ عوض میکند.
- همه‌ی endpointهای §۱۷.۳ با step-up در جاهای 🔏 (هدف step-up طبق §۱۷.۷: `workshop.grant` و `workshop.workspaces` روی sha256 بدنه، `workshop.approval` روی `S-0004/AP-0007` و فقط برای اجازه دادن؛ رد کردن step-up نمیخواهد)، رویدادهای stream (`workshop.session`، `workshop.approval`؛ topicهای `files`، `workshop`، `orders`)، و SSE `/live` با `Last-Event-ID`.
- **`GET /meta`** فیلد `workshop: {runtime}` میگیرد (`null` تا تصمیم مالک) تا اپ‌ها پیش از تلاش بگویند کارگاه هنوز روشن نیست.
- **تصمیم `code_session`** (A1) برای ایجنت‌ها: پیشنهاد سشن با workspace، کارها، بودجه و دلیل؛ مُهر مالک ← grant.
- **قوانین ۱ تا ۷ قرارداد** با کد اجرا میشوند: بودجه‌ی دلاری هر سشن، کلید توقف و توقف deploy، قفل کاری (یک سشن نوشتنی در هر بخش ریپو)، و نگه‌داری transcript کامل در object storage.
- **adapter اجرا** با یک interface و سه پیاده‌سازی:
  - `fake` برای تست و CI (رویدادهای ساختگی، approval، push ساختگی).
  - `managed`: **Claude Managed Agents** (Anthropic حلقه و یک کانتینر جدا برای هر سشن را میچرخاند؛ سیاست مجوز `always_ask` برای push و PR ← `approval_request`؛ اعتبار GitHub در vault آن، در لحظه‌ی خروج جایگزین میشود و هیچ‌وقت داخل sandbox نیست). کد کامل و تست با `fake` HTTP؛ **روشن شدنش منتظر مالک است** (پایین).
  - `self_hosted`: فقط سند طراحی (Claude Agent SDK در کانتینرهای یک‌بارمصرف روی یک هاست سازنده‌ی جدا، نه روی همین سرور). ساخته نمیشود.
- **تا تصمیم مالک:** `POST /workshop/sessions` جواب `503 runtime_not_configured` با `message_fa` روشن میدهد؛ بقیه‌ی کارگاه (workspace، grant، تاریخچه) کار میکند.
- **تست قبولی:** grant بدون مُهر ساخته نمیشود؛ سشن بیرون از grant رد میشود؛ approval با step-up؛ کلید توقف سشن را pause میکند؛ رسیدن به سقف بودجه سشن را متوقف میکند؛ دو سشن نوشتنی روی یک بخش ریپو با هم اجرا نمیشوند؛ هیچ اعتبار GitHub در هیچ رویداد، لاگ یا پاسخ API نیست (اسکن خودکار).

### ۴.۲ تصمیم‌های مالک برای روشن شدن کارگاه (منتظر خود مالک؛ فقط گزارش کن)
1. **محل اجرا:** پیشنهاد Claude سشن مشورت `managed` است (امن‌ترین، بدون بار روی این سرور). این یعنی **یک API key جدا با سقف ماهانه** (پرسش باز شماره‌ی ۲ نقشه‌ی راه). جایگزین: `self_hosted` روی هاست جدا با اشتراک 20x (سهمیه‌ی مشترک با محصولات).
2. **دسترسی GitHub برای هر workspace:** یک توکن fine-grained فقط برای همان یک ریپو، با دسترسی contents و pull requests. مالک میسازد و خودش در OpenBao میگذارد؛ هیچ‌کس مقدارش را نمیبیند.

## ۵. فرمان صوتی (§۱۷.۴)
- **`POST /api/v1/orders`** و `GET /orders`: متن (از `/transcribe` یا تایپ) ← مسیریاب: **اول قاعده** (نام شرکت، نام نقش، کلیدواژه‌ها از فایل seed)، **بعد مدل سبک** با `json_schema` (`{routes: [{company, to, kind, summary_fa}]}`)، **مشاور فقط وقتی مبهم است**.
- `kind: "work"` ← همان مسیر «فرمان تازه» (کار برای مدیرعامل یا مستقیم مدیر، §۴ میانبر)؛ `code` ← کارگاه (سشن جاری مناسب، یا سشن تازه زیر grant، یا تصمیم `code_session`)؛ `question` ← thread مشاور؛ `meeting` ← فعلاً یک کار برای مدیرعامل همان شرکت تا اتاق جلسه ساخته شود.
- فرمان، صدایش و مسیرهایش نگه داشته میشوند و در پلنر مالک میایند. رویداد `order.routed`.
- **تست قبولی:** «به مدیر فنی FX بگو …» بدون مدل به `FX-TECH-MGR` میرسد؛ فرمان مبهم به مشاور میرود؛ فرمان کد بدون grant یک تصمیم `code_session` میسازد؛ عمق ارجاع ۲ شکسته نمیشود.
