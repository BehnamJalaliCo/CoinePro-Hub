## اولویت ۱ (دستور مالک): هر باگ پیدا و درست شود، پیش از هر قابلیت تازه
> **گفته‌ی مالک (۲۰۲۶-۱۱-۰۵):**
> «کلی باگ داره سیستم … مدلی که برای صوت خودمون گذاشتید خیلی مزخرفه … یا کلا برشدارید از api استفاده کنیم … هیچی از هیچی خبر نداشت. من یه کارگروه فرستادم برای استخدام هیچ خبری نشد. به مدیرعامل پیام میدم خبری نمیشه … هر جوری شده باید هر باگی که داره در بیاد. من هر روز دنبال باگ گرفتنم.»

### باگ‌های شناخته‌شده
1. **`GET /work/{id}/tree-events` → 422 (ریشه پیدا شد):**
   - **علت:** اپ اندروید `limit=500` میفرستد (`apps/android/app/src/main/java/com/coinepro/hq/core/net/Api.kt:304`)، ولی هاب حداکثر `pagination.MAX_LIMIT = 200` را میپذیرد.
   - **اثر:** صفحه‌ی کار و گزارش فرمان درخت کامل را نمیبینند.
   - **اصلاح:** اپ `limit=200` بفرستد و تا `next` ادامه بدهد.
   - **سنجش عمومی:** یک تست بنویس که همه‌ی فراخوانی‌های اپ‌ها را با OpenAPI مقایسه کند: سقف‌ها، enumها و پارامترهای اجباری، برای اندروید و وب.
2. **قطع استریم زنده در «گفتگو»:** `GET /stream` → `SocketTimeoutException` در اپ.
   - **چه بسنجی:** timeout خواندن اپ، keep-alive سرور (فاصله‌ی ping در SSE)، و تنظیم Caddy برای stream.
3. **«گفتگو» از هیچ چیز خبر نداشت:**
   - **از کجا شروع کنی:** روی هاب `talk.turns`، `talk.turn_events` و `llm.calls` (task class `talk_turn`) را بخوان.
   - **چه بسنجی:**
     - آیا ابزارهای خواندن واقعاً اجرا شدند؟ گزارش سازنده میگوید: «اگر کارمند نقش در run خودش باشد، نوبت بی خواندن جواب میدهد».
     - آیا «now pack» فرمان‌ها، کارگروه‌ها و استخدام‌ها را دارد؟
     - آیا مغز جواب داده، یا خط «به مغزم دسترسی ندارم» آمده است؟
   - **اصلاح لازم:** منشی و مشاور باید وضع واقعی فرمان‌ها، کارگروه‌ها، استخدام‌ها و پیام‌های مدیرها را ببینند.
4. **کارگروه استخدام فرستاده شد و هیچ اتفاقی نیفتاد:**
   - **علت محتمل:** در وضعیت هفته‌ی ۱ آمده که «هیچ شرکتی پاکت ماه ندارد، پس استخدام خودکار رد میشود». کلید توقف هلدینگ هم تا ۱۱-۰۵ روشن بود.
   - **چه بسنجی:** گزارش آن فرمان (`/orders/{ref}/report`)، blockerها، و runها.
   - **اصلاح لازم:** هر جا کاری به خاطر نبودن پاکت یا قفل رد میشود، باید یک خط روشن به مالک برسد، با دکمه‌ی رفعش. سکوت ممنوع است.
5. **پیام به مدیرعامل جواب نگرفت:**
   - **چه بسنجی:** آیا پیام thread مدیرعامل یک run میسازد؟ آیا سهمیه‌ی `claude-max` و صف Router اجازه میدهد؟ آیا خطا در `agents.runs` هست؟
   - **قانون:** هر پیام مالک باید در چند دقیقه جواب یا دلیل روشن بگیرد.
6. **صدای محلی Piper بی‌کیفیت است:**
   - **تصمیم مالک:** «یا رم را ارتقا دهیم و مدل خوب بیاوریم، یا کلاً برداریم و از API استفاده کنیم».
   - **پیشنهاد Claude ساخت:** Piper را از زنجیره بردار و فقط Gemini API باشد (Flash برای منشی، Flash-Lite برای بقیه). اگر Gemini در دسترس نبود، جواب متنی بیاید، نه صدای بد.
   - **حافظه:** اگر پرامپت ۲۳.۱ پروفایل `tts` را روشن کرده، با `make tts-off` حافظه آزاد شود.
   - **اجرا:** پیش از اجرا، از مالک تأیید بگیر.

### روش جست‌وجوی کامل باگ (پیشنهاد)
- **لاگ‌های هاب ۴۸ ساعت گذشته (از Claude هاب بخواه):**

- **یک فرمان واقعی از اول تا آخر:** «یک پست اینستاگرام برای کوینه‌پرو». هر جا گیر کرد، همان باگ است.

## درس‌ها
- **نام‌ها:** نام مدل‌های Pydantic در کل API یکتا باشد. وگرنه FastAPI نام schema را عوض میکند و تست‌های اندروید میشکنند.
- **record:** حین اجرای `record` در CI روی همان شاخه push نکن.
- **gitleaks:** هم تاریخچه را میخواند هم درخت کاری. برای هر مثبت کاذب، هر دو اثر انگشت لازم است (`<commit>:file:rule:line` و `/scan/file:rule:line`).
- **compose:** رمز پروفایل خاموش را با `:?` اجباری نکن. نشانی شبکه‌ی تازه نباید تکراری باشد.
- **حافظه:** گیت حافظه هر پروفایل را فقط با `full` میسنجد، ولی هاب پروفایل‌های دیگری هم روشن دارد.
- **دیسک نشست ابری:** کم است. worktreeهای تمام‌شده را پاک کن.
