> «کلی باگ داره سیستم … هیچی از هیچی خبر نداشت. من یه کارگروه فرستادم برای استخدام هیچ خبری نشد. به مدیرعامل پیام میدم خبری نمیشه … هر جوری شده باید هر باگی که داره در بیاد.»

## بخش ۱: بررسی پیش از deploy (فقط خواندنی، هیچ تغییری نده)
این بخش وضع فعلی را ثبت میکند تا بعد از deploy معلوم شود چه چیزی درست شد. هر بند را با **عدد** در گزارش بنویس.
- **ممنوع:** متن پیام‌ها، متن فرمان‌ها و هر رمزی. فقط شمار، کد، ref و زمان.
- **بازه:** ۴۸ ساعت گذشته.

1. **لاگ api:**
   - شمار پاسخ‌های 4xx و 5xx به تفکیک مسیر. مسیر را به‌شکل الگو بنویس (`/work/{id}/tree-events`)، نه با شناسه.
   - ۲۰ مسیر پرتکرار.
2. **worker و Temporal:** خطاها به تفکیک activity یا workflow، و شمار هر کدام.
3. **`agents.runs`:**
   - شمار به تفکیک `state` و `error_code`.
   - **گیرکرده‌ها:** runهای `queued` بیش از ۳۰ دقیقه و runهای `running` بیش از یک ساعت، به تفکیک `trigger`.
   - **talk:** شمار runهای `trigger = 'talk'` که هنوز `running` هستند، و قدیمی‌ترینشان.
4. **پیام‌های بی‌جواب مالک:** threadهایی که پیام آخرشان از مالک است (کد thread و عمر پیام، بی متن). برای هر کدام وضع آخرین run آن thread را بنویس.
5. **فرمان‌های باز:** از `owner.order_reports` هر فرمانی که `ended_at` ندارد: ref، state و عنوان blockerها.
6. **کارگروه‌ها:**
   - جایگاه‌های خالی هر عضویت (`growth.memberships.seats`).
   - حالت استخدام (`hiring mode`).
   - اینکه هر شرکت پاکت این ماه دارد یا نه.
7. **قفل‌ها:** `control.lock_state` هر شرکت.
8. **گفتگو:**
   - `talk.turns` به تفکیک `state`، و پرتکرارترین `reason_fa`ها.
   - `llm.calls` با task class `talk_turn` به تفکیک وضعیت و کد خطا.
   - شمار نوبت‌هایی که جوابشان خط «به مغزم دسترسی ندارم» بوده است.
9. **سقف‌ها:**
   - `AGENT_DAILY_TOKEN_CAP` (فقط عدد) و مصرف امروز هلدینگ.
   - شمار runهایی که امروز با `daily_cap` رد شده‌اند.

## بخش ۲: چه درست شده (کد آماده است)
1. **`GET /work/{id}/tree-events` → 422:**
   - **علت:** اپ اندروید `limit=500` میفرستاد و سقف هاب ۲۰۰ است.
   - **اصلاح:** هر دو اپ صفحه‌به‌صفحه با ۲۰۰ تا آخر درخت میخوانند.
   - **gate تازه‌ی `clients-api`** در `make check`: همه‌ی فراخوانی‌های هر دو اپ را با OpenAPI میسنجد، هم مسیر و هم سقف `limit`.
2. **قطع استریم زنده (`SocketTimeoutException`):**
   - **علت:** heartbeat فقط وقتی میرفت که bus بیکار بود. وقتی bus پر از رویدادهای شرکت یا موضوع دیگری بود، چند دقیقه چیزی نوشته نمیشد و اپ بعد از ۵۰ ثانیه قطع میکرد.
   - **اصلاح:** heartbeat حالا با ساعت میرود، هر ۱۵ ثانیه.
3. **گفتگوی بی‌خبر و مدیرعامل بی‌جواب (migration `0045`):**
   - **علت اول:** run گفتگو با قاعده‌ی «یک run در حال اجرا برای هر کارمند» یکی بود. وقتی منشی یا مدیرعامل سر کار بود، گفتگو نمیتوانست بخواند و کورکورانه جواب میداد. وقتی گفتگو باز بود، run خود کارمند (جواب پیام مالک) شروع نمیشد.
   - **علت دوم:** run گفتگویی که worker وسطش متوقف شده بود (deploy، restart) برای همیشه `running` میماند و کارمند برای همیشه «مشغول» بود.
   - **اصلاح:**
     - run گفتگو دیگر کارمند را مشغول نمیکند.
     - run گفتگویی که توکنش منقضی شده، در هر گفتگوی تازه و در جاروی ۵ دقیقه‌ای worker، `failed` با کد `talk_expired` میشود.
   - **«الان» گفتگو:** حالا این‌ها را هم دارد: فرمان‌های باز هفته و مانع هر کدام، کارگروه‌ها و جایگاه‌های خالی، استخدام‌های هفته، آخرین حرف مدیرها، پیام‌های بی‌جواب مالک و کلیدهای توقف.
4. **سکوت ممنوع:**
   - **پیام بی‌جواب:** هر پیام مالک که ۵ دقیقه بی‌جواب بماند، یک اعلان فارسی ساده با دلیل میگیرد، فقط یک بار. دلیل یکی از این‌هاست: رد شد (کلید توقف، سقف روز، بودجه)، کارمند مشغول یا غیرفعال است، یا thread کسی را ندارد.
   - **جایگاه خالی کارگروه:** اگر استخدام خودکار نتوانست جایگاه را پر کند، دلیل روی جایگاه میماند (`blocked`، در `GET /groups/{key}/members`). مالک روزی یک بار با راه رفع خبر میشود، مثلاً «پاکت ماه تعیین نشده است».

5. **بروکراسی کمتر (مالک: «بروکراسی خیلی شدیدی به کار رفته»):**
   - **کارهای روزمره:** ۲۱ کار (`stepup.LIGHT`) دیگر اثر انگشت نمیخواهند. پاسخ `POST /auth/step-up/options` برای آن‌ها خودِ توکن یک‌باره است.
   - **کارهای سنگین:** فرستادن به بیرون، خرج، امضا، حذف و دسترسی مثل قبل passkey میخواهند.
   - **تست:** `tests/test_w5_no_silence.py`.
6. **صدا (تصمیم مالک، ۲۰۲۶-۱۱-۰۵):**
   - **مالک:** «یا رم را ارتقا دهیم و مدل خوب بیاوریم، یا کلاً برداریم و از API استفاده کنیم».
   - **چرا ارتقای رم کمکی نمیکند:** رم آزاد هست. مدل‌های طبیعی فارسی کارت گرافیک میخواهند.
   - **تصمیم:**
     - **صدای اصلی:** Gemini.
     - **صدای محلی:** پیش‌فرض خاموش است (`owner.settings.voice.local = false`). جمله‌ای که هیچ موتور Gemini نتوانست بگوید، **متن میماند**؛ صدای بد پخش نمیشود.
     - **آزمون کور:** یک صدای تازه‌ی محلی به آن اضافه شد: **Mana Persian Piper**. صدای زن است، آموزش‌دیده روی ۸۶ ساعت گفتار فارسی Mana، با وزن‌های MIT و داده‌ی CC0. در image صدا با sha256 پین شده است.
     - **اگر مالک یکی را پسندید:** همان پشتیبان محلی میشود.

## بخش ۳: deploy
1. `git pull` روی شاخه‌ی اصلی و ساختن `server/p23-2-deploy`. `make check` را در worktree جدا اجرا کن؛ gate تازه‌ی `clients-api` هم در آن است. اجازه‌ی دائمی قالب‌بندی و CVE سر جایش است.
2. `make backup`.
3. فقط image‌های `api` و `worker` را بساز و بالا بیاور، بعد `make verify-live`.
4. **سنجش‌ها** (عدد یا بله/خیر):
   - `alembic current` = `0045`.
   - **runهای talk قدیمی:** شمار runهای talk که پیش از deploy `running` بودند و حالا `failed` با `talk_expired` شده‌اند. حداکثر ۵ دقیقه بعد از بالا آمدن worker.
   - **مشغول بی‌دلیل:** هیچ کارمندی نباید فقط به خاطر run گفتگو مشغول باشد.
   - **پیام‌های بی‌جواب:** برای هر پیام بی‌جواب بند ۴ بخش ۱، حالا یا جواب آمده یا یک اعلان با دلیل. شمار هر دو را بنویس.
   - **کارگروه:** جایگاه‌های خالی حالا `blocked` با دلیل دارند (شمار به تفکیک کد).
   - **استریم:** با `curl -N` روی `/api/v1/stream` با یک topic کم‌رفت‌وآمد، دست‌کم یک `: heartbeat` در هر ۱۵ ثانیه. از نشست مالک، بدون چاپ توکن.
5. **آزمون رفت‌وبرگشت migration روی هاب انجام نده.**

## بخش ۴: صدای محلی (بعد از سبز شدن بخش ۳)
1. **ساخت:** image `tts` را بساز تا صدای تازه‌ی `fa_IR-mana-medium` در آن باشد. timer آن را روشن **نکن**.
2. **ثبت:** با بالا آمدن api، ردیف `manatts-piper` در `media.voices` باید `runtime` بگیرد. بسنج: `GET /api/v1/media/voices` → `manatts-piper.installed = true`.
3. **نمونه‌ها:** صف آزمون روزانه (`voice_bakeoff`) نمونه‌های این صدا را میسازد. برای اینکه مالک امروز گوش بدهد، یک بار دستی بسازشان:
   - activity را صدا بزن، یا تا گذر بعدی صبر کن.
   - `infra/tts/run-once.sh` را **یک بار** اجرا کن. اگر حافظه‌ی پروفایل جا نشد، پیش از اجرا با `free -h` بسنج که دست‌کم ۱ گیگ واقعاً آزاد است.
   - **گزارش:** شمار نمونه‌های ساخته‌شده‌ی هر صدا.
4. **پیام به مالک:** «نمونه‌ها آماده‌اند؛ در اپ، صفحه‌ی صداها، آزمون کور را گوش بدهید و نمره بدهید.»
5. **فقط بعد از گفته‌ی مالک:**
   - اگر یک صدای محلی را انتخاب کرد (نمره‌ی ۷ یا بیشتر)، `HQ_TTS_VOICE` را همان صدا بگذار، `PUT /owner/settings` با `voice.local = true` (نسخه‌ی تازه، از نشست مالک)، و Piper را طبق مرحله‌ی ۲ پرامپت ۲۳ روشن کن.
   - **حافظه:** اگر جا نشد، فقط بگو کدام پروفایل باید خاموش شود. خودت خاموش نکن.
   - اگر هیچ صدایی را نپسندید، کاری نکن. صدای محلی خاموش میماند و جواب‌ها متن میمانند.
