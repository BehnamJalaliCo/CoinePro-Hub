## چه شد (کوتاه)
- **گفتگو:** صفحه‌ی «گفتگو» در اپ، جدا از دکمه‌ی زرد. مالک با منشی هلدینگ، ناظر کل، دستیار شخصی، مشاور کل و هر مدیر هر شرکت حرف میزند. هر نوبت روی worker اجرا میشود (workflow `TalkTurn`) و Router آن را با task class `talk_turn` جواب میدهد. ابزارها فقط‌خواندنی‌اند، از Tool Gateway رد میشوند و دروازه‌ی run فقط A0 را قبول میکند. پیش‌فرض «مشورت» است. کار فقط از راه کارت و با مسیرهای موجود ساخته میشود.
- **صدا:** Gemini 3.8 Flash TTS و Flash-Lite از راه egress (کانال `gemini-tts`، فقط میزبان `generativelanguage.googleapis.com`)؛ Piper همیشه آخرین موتور است.
  - کلید را api در OpenBao (`kv/hq/voice/google`) مینویسد و هرگز دوباره نمیخواند. worker آن را برای یک فراخوانی میخواند و به egress میدهد.
  - صدا روی worker با ffmpeg به Opus تبدیل میشود.
- **کنتور و سقف:** هر جمله یک ردیف مصرف دارد، با شمارش توکن خود گوگل. سقف ماه را فقط مالک میگذارد. اگر سقف پر شود یا موتور خطا بدهد، جمله‌ی بعدی با موتور بعدی گفته میشود.
- **زمان‌بندی:** `hq-voice-check` هر ۶ ساعت (فقط فراخوانی رایگان metadata).

## deploy، مرحله‌ی ۱: کد و داده
1. `git pull` روی شاخه‌ی اصلی و ساختن شاخه‌ی `server/p23-deploy`. `make check` را در worktree جدا اجرا کن، `services/scripts/browser-test.sh` را هم. اجازه‌ی دائمی قالب‌بندی و CVE سر جایش است.
2. `make backup`.
3. `make llm-provision`. policyهای OpenBao دوباره نوشته میشوند: api فقط مینویسد در `kv/hq/voice/*` و worker فقط میخواند. هیچ رمزی نساز و چاپ نکن.
4. image‌ها را بساز و بالا بیاور، بعد `make verify-live`:
   - `api`
   - `worker` (workflowهای `TalkTurn`، `VoiceCall` و `VoiceCheck`)
   - `gateway`
   - `llm-router` (task classهای `talk_turn` و `talk_summary`)
   - `egress` (کانال `gemini-tts`)
   - `tts` (حالت serving؛ فقط build، روشن کردن در مرحله‌ی ۲)
5. **سنجش‌ها (عدد یا بله/خیر):**
   - `alembic current` = `0044`.
   - `GET /api/v1/talk/personas`: تعداد نقش‌ها.
   - `GET /api/v1/voice/engines`: باید ۳ موتور باشد. دو موتور Gemini تا مالک کلید نداده `missing` هستند، و این درست است.
   - `GET /api/v1/voice/meter?period=month`: باید ۲۰۰ باشد با `voice_usd` = 0.
   - زمان‌بندی `hq-voice-check` در Temporal هست.
   - task classهای `talk_turn` و `talk_summary` در Router هستند.
   - **حافظه:** آزاد بودن حافظه‌ی سرور را بنویس، و اینکه با پروفایل `tts` و `TTS_SERVE_S=110` در بودجه‌ی حافظه جا میشود یا نه.
6. **آزمون رفت‌وبرگشت migration روی هاب انجام نده.**

## deploy، مرحله‌ی ۲: فقط وقتی مالک گفت
- **صدای محلی Piper (پشتیبان رایگان):** در `.env` بگذار `HQ_TTS=on` و `TTS_SERVE_S=110`. timer آن را دوباره بخوان.
  - **اثر:** هر گذر ۱۱۰ ثانیه بیدار میماند و جمله‌های گفتگو را حدود یک‌ثانیه‌ای میگوید. در این مدت قفل one-shot را نگه میدارد، پس backup ساعتی حداکثر همین‌قدر صبر میکند.
  - **سنجش:** یک جمله‌ی نمونه با Piper (`POST /voice/sample` با engine `piper`) فایل صوتی میسازد.
- **کلید Gemini:** کار خود مالک است، در خود چت اپ با دکمه‌ی 🔑. تو فقط بعد از آن بنویس:
  - وضعیت دو موتور Gemini (`ok` یا دلیل)؛
  - اینکه ردیف مصرف جمله‌ی «سلام» ثبت شده است.

## سنجش پس از deploy (با عدد، یک روز بعد از اولین استفاده‌ی مالک)
- **مصرف ۲۴ ساعت:**
  - توکن‌های `talk_turn` و `talk_summary` (از `llm.calls`)؛
  - دلار صدا به تفکیک موتور (از `talk.voice_usage`).
- **سرعت:** میانه‌ی زمان از ثبت نوبت مالک تا اولین رویداد `audio` (از `talk.turn_events`). هدف ۳ ثانیه یا کمتر است.
- **مشورت:** تعداد گفتگوهای حالت مشورت که فرمانی ساخته‌اند. باید ۰ باشد، مگر با کارتی که مالک زده است.

## قوانین
- **رمزها:** هیچ رمز، توکن یا کلیدی چاپ نشود، فقط نام متغیرها. کلید Gemini را مالک در اپ میدهد. اگر لازم شد، فقط نام مسیر OpenBao را بنویس.
- **مرز تصمیم:** سقف ماه، زنجیره‌ی موتورها، روشن کردن `HQ_TTS` و هزینه با مالک است.
- **سرورها:** به هیچ سرور شرکتی وصل نشو.
- **شبکه:** خروجی تازه فقط `generativelanguage.googleapis.com` از egress است. اگر قانون فایروال لازم شد، فقط گزارش بده.
- **گزارش:** در پایان، گزارش کوتاه فارسی به مالک بنویس، با قدم بعدی او از `docs/server-prompts/builder-w3/OWNER_STEPS.md`.
