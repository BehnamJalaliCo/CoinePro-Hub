# پرامپت ۲۸.۱: پورت ۲۲ دیگر «مسیر قطع» نیست (deploy)

> Claude سشن مشورت، ۲۰۲۶-۱۱-۰۸. کد نوشته و تست شده است.
> - **پیش‌نیاز:** پرامپت ۲۸ deploy و سبز (`alembic current` = `0058`).
> - **شاخه:** `server/p28-1-deploy` از سر شاخه‌ی اصلی، بعد از pull.
> - **گزارش:** `docs/ops/reports/PROMPT_28_1.md`.
> - **migration:** ندارد.
> - **اپ‌ها:** 0.19.1.

## چرا
مالک صفحه‌ی «شبکه‌ی هلدینگ» را دید که میگفت «۱۲ مسیر قطع است». همه‌ی آن ۱۲ مسیر پورت ۲۲ بودند، یعنی ورود SSH از یک سرور شرکت به سرور شرکت دیگر:
- فایروال هر شرکت این پورت را عمداً بسته نگه میدارد.
- کار هلدینگ هرگز از این راه نمیگذرد. runner‌ها و هر درخواستی با HTTPS از هاب میگذرند.

حالا هاب پورت ۲۲ را میان سرورها نمیسنجد و نتیجه‌های قدیمی آن را هم در نقشه و در دلیل وضعیت سرور نشان نمیدهد. پورت‌های ۴۴۳ و ۸۰ مثل قبل سنجیده میشوند.

## deploy
1. **شاخه و سنجش:**
   - شاخه‌ی اصلی را `git pull` کن و `server/p28-1-deploy` را بساز.
   - `make check` را در worktree جدا اجرا کن.
   - اجازه‌ی دائمی قالب‌بندی و CVE سر جایش است.
2. `make backup`.
3. **image‌ها:** این‌ها را بساز و بالا بیاور، بعد `make verify-live`:
   - `api` (worker با همین image)
   - `web` (پروفایل `web`، 0.19.1)
4. **سنجش‌ها** (عدد یا بله/خیر، بی هیچ رمز):
   - `POST /api/v1/infra/network/check` را یک بار بزن. این کار همان «بررسی دوباره»ی خود اپ است و فقط میخواند.
   - بعد از یک دقیقه، از `GET /api/v1/infra/network` بنویس:
     - شمار مسیرهای قطع
     - آیا هیچ مسیری با پورت ۲۲ در آن هست (بله/خیر)
   - **وب:** `https://hq.coinepro.com/healthz` جواب ۲۰۰ میدهد و نسخه‌ی پنل 0.19.1 است.
5. **آزمون رفت‌وبرگشت migration روی هاب انجام نده.**
