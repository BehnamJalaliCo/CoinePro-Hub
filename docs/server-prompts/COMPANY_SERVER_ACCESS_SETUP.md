# آماده کردن سرور یک شرکت برای دسترسی هلدینگ

> - **برای Claude خود هر سرور شرکت** (FX، TY، PC و بعدی‌ها)، نه Claude هاب.
> - **مالک** این فایل را به Claude همان سرور میدهد، همراه با **کلید عمومی** که هاب در پرامپت ۱۷ چاپ میکند.
> - **تصمیم مالک (۲۰۲۶-۱۰-۳۰):** هلدینگ به همه‌ی سرورهای شرکت‌ها دسترسی کامل دارد (قرارداد هاب §۲۶).

## کار
1. **کاربر کاری:** هاب با همین کاربر وارد میشود، کاربری که Claude Code، Docker و git این سرور با آن کار میکنند (مثلاً `forex`).
2. **کلید هاب** را به `~/.ssh/authorized_keys` همین کاربر اضافه کن، دقیقاً با این قیدها:
   ```
   from="10.10.1.4",no-agent-forwarding,no-X11-forwarding,no-port-forwarding <کلید عمومی که مالک داد>
   ```
   - **مجوز فایل‌ها:** `~/.ssh` با `700` و `authorized_keys` با `600`.
3. **sshd:** روی IP خصوصی همین سرور هم گوش بدهد. `PasswordAuthentication no` بماند. sshd را **reload** کن، نه restart، و پیش از reload با `sshd -t` بسنج.
4. **sudo:** اگر این کاربر sudo بی‌رمز ندارد، به اجازه‌ی مالک یک فایل `/etc/sudoers.d/hq` بساز و با `visudo -c` بسنج.
5. **Claude Code و git:** Claude Code همین کاربر login باشد و git همین کاربر بتواند به remote ریپوها push کند. هر دو را بسنج، بدون چاپ رمز.
6. **گزارش به مالک،** فارسی و کوتاه، فقط این‌ها:
   - نام سرور و IP خصوصی
   - نام کاربر
   - **اثر انگشت host key:**
     ```
     ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
     ```
     مقدار `SHA256:…`.
   - مسیر ریپوها
   - فهرست سرویس‌ها، compose، n8n و cronها

## مالک بعد از آن
گزارش را به هاب بده تا `make company-ops-attach` را کامل کند. از آن لحظه:
- ایجنت‌های ستاد روی این سرور کار میکنند.
- هر کارشان در اپ دیده میشود: صفحه‌ی شرکت ← «سرورها».

## قوانین
- **رمز:** هیچ رمز یا کلید خصوصی چاپ نشود.
- **فایروال:** به فایروال دست نزن. شبکه‌ی خصوصی هتزنر از قبل باز است.
- **کاربر و رمز:** هیچ کاربر دیگری حذف یا عوض نشود و رمزی تغییر نکند.
