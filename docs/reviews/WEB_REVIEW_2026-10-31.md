# بازبینی مستقل پنل وب — ۲۰۲۶-۱۰-۳۱

**دامنه:** `apps/web` در نسخه‌ی 0.9.0، مقایسه‌شده با اپ اندروید، قرارداد `contracts/HQ_CORE_API_v1.md` و کد واقعی سرور در `apps/api`.
**روش:** بازبینی فقط‌خواندنی بود و هیچ فایل منبعی تغییر نکرد. ابزارهایی که اجرا شدند:
- `npm run typecheck`، `npm run lint` و `npm run build`
- `next dev` در حالت mock و Playwright روی ۷۱ صفحه در چهار نما: دسکتاپ و گوشی، روز و شب
- ساخت production با mock و `next start`، برای دیدن CSP و hydration واقعی
- مقایسه‌ی خودکار سه چیز با سرور: ۳۸۴ فراخوانی API و پارامترهایشان، نام‌های step-up، و نوع رویدادهای SSE

**نکته‌ی زمانی:** در حین بازبینی، نشست دیگری روی ⟨1.10⟩ کار میکرد (`v28.ts`، `outputs`، `watch`، `error-upload`). یافته‌ها روی کد پایدار است. موردهای اعلام‌شده (چندانتخابی خروجی‌ها، placeholder «O-…»، دلیل خام شکست شورا) تکرار نشده‌اند.

**آنچه سالم بود (برای اینکه دوباره وقت نگیرد):**
- typecheck و lint تمیزند و build موفق است.
- هر ۳۸۴ فراخوانی (روش و مسیر) با یک route واقعی سرور جور است.
- همه‌ی نام‌های step-up با `stepup.consume` سرور یکی است.
- در ۲۸۴ بارگذاری صفحه، هیچ خطای hydration یا console نبود (به‌جز ۴۰۴ عمدی).
- فیکسچرهای mock وارد bundle تولید نمیشوند.
- `Md` هیچ HTML خامی رندر نمیکند. تنها `dangerouslySetInnerHTML` همان اسکریپت تم با nonce است.
- پوشاندن داده در خطاخوان دقیق است.
- کنتراست توکن‌های رنگ تقریباً همه ≥ 4.5 است.

## بالا (High)

### H1. استریم زنده بعد از دو اتصال ناموفق، برای همیشه فقط به موضوع‌های پایه گوش میدهد
- **کجا:** `src/lib/stream.ts:175-187`
- **چه میشود:** اتصال اول (`i === 0`) دو بار پیاپی پیش از باز شدن شکست میخورد. این دقیقاً همان سناریوی «راه‌اندازی دوباره‌ی هاب» در 0.4.0 است، یا بیدار شدن لپ‌تاپ بی‌اینترنت.
  - در این حالت `coreOnly = true` میشود و تا بستن زبانه همان میماند.
  - اتصال‌های ۲ و ۳ دیگر باز نمیشوند (`if (coreOnly && i > 0) return`).
  - اتصال اول هم فقط `CORE_TOPICS` را میخواهد.
- **اثر برای مالک:** بعد از یک ری‌استارت، پنل باز ظاهراً «زنده» است. ولی این‌ها دیگر زنده به‌روز نمیشوند تا صفحه را رفرش کند:
  - سرورها، فرمان‌ها، اجرای ایجنت‌ها، تأسیس، بایگانی، جلسه‌ها
  - هشدارهای مرورگر برای این رویدادها
- **چرا:** این fallback برای هاب‌های پیش از ⟨1.4.2⟩ بود که موضوع ناشناخته را 422 میکردند. امروز `routes/stream.py` موضوع ناشناخته را نادیده میگیرد، پس دیگر لازم نیست.
- **پیشنهاد:** fallback را حذف کن. یا دست‌کم فقط وقتی فعال شود که پاسخ واقعاً 422 باشد، نه هر خطا.

### H2. اتصال دوباره‌ی استریم `Last-Event-ID` را گم میکند و رویدادهای دوره‌ی قطعی از دست میروند

  - توضیح کد میگوید «the browser does it»، ولی با close دستی مرورگر این کار را نمیکند.
- **اثر:**
  - رویدادهای ثانیه‌ها تا دقیقه‌های قطعی (ری‌استارت هاب، قطع Wi-Fi) هرگز نمیرسند.
  - کش‌ها تا refetch بعدی کهنه میمانند.
  - AlertCenter اعلان «تحویل فرمان» یا «کارت تازه» همان دوره را نمیدهد.

### M1. CSP در production استایلی را که Radix تزریق میکند مسدود میکند
