## ۳. جمع‌بندی نظر ChatGPT

**پذیرفته شد:**
- **Gateway** به‌عنوان یک PEP غیرقابل‌دورزدن.
- **شبکه‌ی خصوصی هتزنر رمزنگاری ندارد،** پس TLS، mTLS یا WireGuard لازم است.
- **دسترسی به دیتابیس** فقط با Query Template (هرگز SQL خام).
- **استقلال برای هر اکشن جدا تعیین میشود.** کلاس‌های اکشن A0 تا A4؛ A4 (مالی و برگشت‌ناپذیر) برای AI ممنوع است.
- **ترفیع** فقط با eval و ۳۰ اجرای shadow.
- **Idempotency، Dry-run، Evidence Ledger و Audit غیرقابل‌تغییر.**
- **ModelAdapter،** تا هسته به یک ارائه‌دهنده قفل نشود.
- **تلگرام فقط کانال ثانویه** است؛ هیچ تأییدی از تلگرام انجام نمیشود.
- **Health Score در قالب ۳ کارت.**
- **Scenario Lab** به جای ادعای «دوقلوی دیجیتال». دفتر 3D در اولویت P3.
- **جلسات** با Evidence Freeze؛ رأی ایجنت‌ها جای امضای مالک را نمیگیرد.
- **۳ ایده‌ی جسورانه:** Autonomy Escrow (پاکت اختیار)، Agent SimGym (باشگاه آزمون)، Opportunity Exchange (بازار داخلی پروژه).
- **۳۰ سؤال از مالک:** خلاصه شد به ۱۰ سؤال با پیش‌فرض، که مالک قبولشان کرد.

**اصلاح شد:**
- **قیمت مدل‌ها:** ChatGPT با نسل قبل حساب کرده بود؛ با قیمت‌های فعلی هزینه تقریباً نصف میشود. حالا که همه‌چیز روی اشتراک 20x است، **هزینه‌ی اضافه‌ی Claude نزدیک صفر است**، با این شرط که سهمیه رعایت شود.
- **نقشه‌ی راه:** ChatGPT آن را با فرض ۳ برنامه‌نویس انسانی ساخته بود. توسعه با Claude Code است؛ گلوگاه اصلی تصمیم‌ها و دسترسی‌های مالک است.
- **منشی:** کاملاً حذف شد. گزارش صبحگاهی یک تابع سیستمی است.

**جمله‌ی کلیدی ChatGPT که پذیرفته شد:** «اول مجوز و سیاست بیرون از LLM، اول شاهد و ارزیابی قبل از استقلال، اول اقتصاد واحد قبل از مقیاس.»

## ۴. یافته‌های بررسی ریپوها (فقط خواندنی)

### ۴.۱ Claude داخل داکر
| | TradeYar `claude-bridge` | FX `claude-llm` |
|---|---|---|
| پیاده‌سازی | Python، ۷۲۱ خط، روی `claude -p` | Node، ۱۵۹ خط، روی `claude -p` |
| احراز هویت Claude | توکن اشتراک | توکن اشتراک |
| نقاط قوت | stream، `--resume`، قالب دستورها | صف همزمانی ۳تایی، system prompt جایگزین، prompt بزرگ از stdin، نسخه‌ی ثابت CLI، پشتیبانی تصویر |
| نقاط ضعف | سوکت داکر، کلید SSH و ریپوی قابل نوشتن mount شده‌اند؛ `--dangerously-skip-permissions`؛ رمز سرویس اختیاری؛ نسخه‌ی CLI ثابت نیست؛ بدون سقف همزمانی | سرویس هیچ رمزی ندارد |
| مشکل‌های ثبت‌شده | لایه‌ی Claude Intel قفل شده و ۱۰۰٪ خطا میدهد (هفته‌ای حدود ۵۵ هزار ردیف)؛ تولید درس‌های آکادمی از ۲۰۲۶-۰۶-۰۴ متوقف است؛ برخورد با سقف اشتراک | کرش E2BIG (رفع شده)؛ برخورد با سقف هفتگی |

### ۴.۲ مدل کسب‌وکار (از کد TradeYar)
- **VIP رایگان است،** به شرط ثبت‌نام با رفرال ما و حداقل ۵۰ USDT موجودی. پس درآمد از کمیسیون رفرال میاید.
- **TradeYar الان بررسی‌کننده‌ی رفرال دارد:** `app/trading/referral_verifier.py` (API افیلیت صرافی) و `app/vip/uid_intake.py`.
- **ممیزی خود TradeYar یک نشتی قیف پیدا کرده:** سه حداقل موجودی متناقض (۵۰ در ربات، ۱۰۰ در پنل، و یک عدد دیگر برای کپی‌ترید).

### ۴.۳ ⚠️ یافته‌ی مهم: مانیتورینگ از شبکه‌ی خصوصی در دسترس نیست
در هر دو سرور، Prometheus (9090)، Alertmanager (9093)، Loki (3100) و Grafana (3000) **فقط روی `127.0.0.1`** باز هستند. نتیجه:
- هاب **بدون هیچ تغییری** فقط این‌ها را میبیند: سلامت عمومی سایت‌ها و APIها از بیرون، و کد روی GitHub.
- **برای دیدن متریک‌ها، هشدارها و لاگ‌ها، اولین CR لازم است (CR-001):** یک مسیر فقط‌خواندنی روی IP خصوصی هر سرور.
  - **روش پیشنهادی (ارسال از سرورها به هاب، کم‌خطرترین):**
    1. Alertmanager یک گیرنده‌ی webhook به هاب اضافه میکند، پس هشدارها لحظه‌ای به هاب میرسند.
    2. Prometheus با `remote_write` (یا federation) متریک‌های انتخابی را به هاب میفرستد.
    3. Promtail یا Loki لاگ‌های فیلترشده را میفرستد.
  - **روش جایگزین:** یک nginx فقط‌خواندنی روی IP خصوصی، فقط برای GET به `/api/v1/query*`، همراه با mTLS و allowlist IP هاب.
  - هر دو روش فقط پیکربندی هستند و به کد محصول دست نمیزنند. **ولی چون روی سرورهای دیگر انجام میشوند، با CR و اجازه‌ی مالک.**
- سرور FX از نظر RAM تنگ است (۱۶GB). روش ارسالی کمترین بار را دارد.

## ۵. معماری نهایی، خلاصه

```text
                CEO: Android + Web (همزمان)            Telegram Support (Business)
                     Passkey + MFA                              │
                          │ HTTPS                               │
 ┌────────────────────────▼─────────────────────────────────────▼──────────┐
 │                  COINEPRO HQ  (Hetzner, CPX42)                          │
 │  API/BFF · Identity · Cartable · Messenger · Meetings · Reports         │
 │  Policy Engine · Decision Log · Audit · Cost & Quota Ledger             │
 │  WorkflowEngine (Postgres jobs) · Postgres+pgvector · Redis            │
 │  ┌──────────────┐  ┌───────────────────┐  ┌──────────────────────────┐  │
 │  │ n8n          │  │ claude-runtime    │  │ TOOL GATEWAY (PEP)       │  │
 │  │ rule-first   │  │ 20x subscription  │  │ scope·quota·DLP·audit    │  │
 │  │ automations  │  │ priority queue    │  │ dry-run·breaker·kill     │  │
 │  └──────────────┘  │ quota governor    │  └───────────┬──────────────┘  │
 │                    └───────────────────┘              │                 │
 └───────────────────────────────────────────────────────┼─────────────────┘
                   Hetzner Cloud Network (eu-central) + TLS/mTLS
              ┌────────────────────┼─────────────────────┐
         TradeYar             CoinePro-FX            Pro-Chart
   (alerts/metrics push · read-only adapters · NO SSH · NO raw SQL)
```

**اصول کلیدی:**
1. **ایجنت‌ها شبکه ندارند.** فقط Gateway ارتباط میگیرد.
2. **اول قاعده (n8n)، آخر Claude.**
3. **صف اولویت Claude:** ① چیزهایی که کاربر میبیند ② هشدار ③ گفت‌وگوی مالک ④ پس‌زمینه.
4. **fallback:** اگر هاب از دسترس خارج شود، TradeYar و FX به کانتینر خودشان برمیگردند. هاب نقطه‌ی شکست محصولات نیست.
5. **کلاس‌های اکشن A0 تا A4** و **پاکت اختیار** (Escrow).
6. **هیچ عددی بدون منبع.**

**Stack:**
- بک‌اند: FastAPI، Postgres 16 + pgvector، Redis
- وب: Next.js PWA
- اندروید: Kotlin/Compose (اپ مستقل)
- n8n
- `claude-runtime` (Claude Code CLI؛ بهترین الگوهای FX و TradeYar، بدون نقاط ضعفشان)
- Docker Compose
- Caddy یا nginx
- Prometheus، Loki و Grafana برای پایش خود هاب
- Uptime بیرونی
