# services/gateway — Tool Gateway (پرامپت ۵ §۳)

تنها راه عمل ایجنت‌ها. ایجنت شبکه، shell و فایل ندارد؛ موتور اجرا (worker) هر اقدامی را که مدل خواسته به این‌جا میدهد و gateway آن را **با توکن `hqa1` همان اجرا** از راه API داخلی انجام میدهد. پس RLS، OPA و Audit همان‌هایی‌اند که برای هر ایجنت هست.

| مرحله | چه چیزی |
|---|---|
| رزرو | اجرای در حال اجرا، سقف فراخوانی ابزار در هر قدم و هر اجرا (در `agents.runs`)، نقش منشور، قفل شرکت |
| کاتالوگ | ابزار ناشناخته ← رد؛ هیچ ابزار A3/A4 وجود ندارد |
| منشور | ابزار بیرون از `tools` منشور نقش ← رد |
| سیاست | `hq.actions` در OPA: کلاس ابزار بر اساس نقش و پاکت اختیار، A4 هرگز، شرکت قفل‌شده ← نوشتن رد |
| اعتبارسنجی | مدل Pydantic هر ابزار (خطای فیلد بدون مقدار) |
| انجام | API داخلی با توکن همان اجرا |
| redaction | کلید، توکن، ایمیل، تلفن، کارت، IBAN و هر فیلد شخصی؛ حجم محدود |
| Audit | یک ردیف برای هر فراخوانی: ابزار، کلاس، نتیجه، ref؛ بدون ورودی و خروجی |

- **شبکه:** فقط `hq-core`؛ هیچ پورت منتشرشده‌ای ندارد؛ به Postgres، NATS، Valkey و OpenBao دسترسی ندارد.
- **احراز:** فقط worker. hash توکن worker در فایل `/run/secrets/hq/worker-token.sha256` (۶۰۰، uid 10001) است و `make up` آن را میگذارد.
- **`github.read`:** ساخته و تست شده، ولی تا مالک توکن فقط‌خواندنی ندهد خاموش است (`channel_not_configured`).
- مستندات کامل: `docs/ops/AGENTS.md`.
